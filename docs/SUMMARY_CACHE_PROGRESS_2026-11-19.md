# 请求去重与摘要缓存（2026-11-19）

承接 `dad4404` 的分页发布。本批不新增表、索引或触发器，schema 仍为 v5，AES_KEY、旧 `plain:` 兼容读取与业务备份范围不变。

## 客户端：不再“反复取消再发一次”

- `SummaryRefresh` 合并 25ms 内的刷新调用，同一会话/后端只维持一个摘要请求。
- 普通读取加入正在进行的请求；请求过程中发生写操作/失效时，合并成一次后续读取，不能把写操作前的结果当作最新。
- 摘要 epoch 使已经失效的旧响应不能更新页面。登出、卸载、切换后端时取消当前请求并清待执行任务，所有等待者都能结束。
- 概览切入、页面重新可见时读取；可见页面最多每 30 秒校验，后台隐藏时不发送轮询。错误后的自动重试间隔也有下限，不进行无限快速重试。
- 概览显示库存快照时间；“刷新快照”显式绕过服务端缓存。此按钮只读库存，不调用上游同步或续期。

## 服务端：暖命中只有一次索引读取

- `cache` 表存有版本的摘要快照，键按算法版本和时区偏移隔离，值不超过 512KiB。
- 命中查询在同一条 SQL 中检查缓存期限、生成时间以及当前 `settings.catalog_summary_revision`；无需再下载全部域名投影、做跨源去重和日期计算。
- 缓存最大 5 分钟；真实到期、90 天预警进入点、月份切换、RDAP 缓存自然过期会提前截断有效期，不能等满 5 分钟。
- 命中时按当前时间更新预警/月份示例的剩余天数，库存计数与快照身份不变。
- 缓存缺失时仍用原全量口径；按来源分组及归一化域名/候选键改为单次分组、单次计算并复用，减少冷计算重复工作。
- 只合并同一绑定/时区正在执行的请求，完成后删除 Promise，不在进程全局保留用户摘要。
- 冷计算期间库存变化，版本条件写入拒绝旧缓存并最多重试一次；持续变化返回失败，而非假成功。
- `X-Catalog-Summary-Cache` 标识 `hit / miss / bypass / joined`。HTTP 响应仍为 `Cache-Control: private, no-store`，避免浏览器/CDN绕开库存版本检查。

## 原子失效与预算

共享 `DatabaseManager` 的 D1 边界把已知库存写入与一个随机版本戳放在同一事务：

- 账号、托管域名、自定义域名、日期覆盖、RDAP 缓存的写操作均失效所有时区快照。
- 单条写使用隐式 batch，已有多条 batch 只追加一次版本写；业务或版本写失败一起回滚。
- 日期覆盖、同步切片、级联删除、直接/分段恢复均经过该边界，不靠路由末尾的非事务“清缓存”。
- 普通 DNS 记录缓存、认证设置和日志不触发摘要失效；摘要自身写入也不失效自己。
- 保持不可变 `bind`、batch 返回长度、`first/all/run/raw`、读副本 session 语义。混用未由同一边界 `prepare` 的语句被拒绝；库存变更不能通过该边界的 `exec` 绕过。
- Node SQLite batch 增补写操作 `RETURNING` 的行与 changes/lastInsertRowid，以便两种运行时行为一致。

不需要扩展 schema，因此现有首次 bootstrap ≤44 / setup ≤50 SQL 门禁保持。正常库存事务会额外写一次版本；包括没有真正改变内容的受保护语句，采取保守失效。

## 已完成验证

- 客户端 20 个刷新调用合并为一次；写入期间失效只补一次读取；强制刷新、退出取消、失败后重试和旧响应抑制有回归。
- 服务端 10,000 条暖命中验证只有一次读且禁止访问库存投影；覆盖持久缓存、绑定/时区隔离、账号/域名/日期/RDAP/恢复失效、业务和版本失败回滚、缓存损坏、跨时间边界、RETURNING 与 session。
- 真实 workerd/D1 和 Node/SQLite 隔离冒烟确认：miss → hit，公开自定义分组/域名 API 写入后 miss，`refresh=1` 为 bypass；原 outbox 生产、投递及去重冒烟仍通过。没有调用真实服务商或修改生产数据。
- 本机 Node/SQLite、10,000 条记录实测：冷摘要 105.873ms，20 次暖命中中位 0.0916ms，最大 0.8329ms。此结果不含 HTTP/D1 网络延迟，不是 Cloudflare CPU 配额或 Core Web Vitals 验收。
- 本地 Chromium + 20,898 条隔离库存确认了快照时间、`hit` 和“刷新快照”强制读取；初始请求及必要补读分别约 219ms /12.3ms，周期读取约 14.8ms。控制台无错误，测试会话、页面与服务已关闭。
- 本批新增 22 个回归，最终全量 `verify:all` 共 332 个用例通过；普通/自建构建、发布包、真实运行时冒烟和 Docker 源码边界检查通过。普通入口 64.31KB gzip，自建 64.25KB，仍低于 80KB 预算。

最终全量构建、浏览器及发布结果以执行日志和对应提交的 Actions 为准。

## 保证边界与限制

- 版本失效保证针对本版本应用写入边界。直接 SQL、D1 控制台、混跑旧后端等绕过它的变更，应点击强制刷新或等待最多 5 分钟；不要把内部修订键当业务设置修改。
- 这不是物化汇总/FTS。冷计算仍为 O(N)，且不同 Worker isolate 的同时冷计算可能重复；条件写入防止旧库存结果覆盖新库存缓存，不承诺“只计算一次”。
- 缓存存储失败时，只要版本确认一致，可以返回新计算但不缓存的结果；版本读取失败则拒绝成功响应。
- 页面每 30 秒自动校验，不宣称另一设备的写入会毫秒级推送到所有已打开页面。
- 超过缓存体积上限时返回原口径的未缓存摘要；超大库存仍需索引/预计算及真实 Workers CPU 测量。
- D1 边界是应用内部协议；新增库存写路径必须使用它的 `prepare/batch`，不能直接操作原始 binding 后假设缓存已失效。
