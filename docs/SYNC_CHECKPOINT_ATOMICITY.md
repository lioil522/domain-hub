# 同步写入与检查点共用租约判断

在 `3b5ab9c` 上用隔离 SQLite 复现了两种进度分裂：

- 在租约截止前 1ms 暂存一页，写入行和检查点分别取时间。前一条 SQL 命中，后一条更新 0 行；`batch()` 本身成功，随后在 JS 抛错并不能回滚已经提交的行。恢复时再次暂存同一页可能遇到主键冲突。
- 队列驱动的 Cloudflare 最后一页先提交库存替换、删除候选及 generation 清理，再单独提交外层 `sync_work.cursor`。第二次提交失败会留下旧游标，此时用来续读的 generation 已经不存在。

## 提交方式

同步工作在网络请求和异步准备完成后，为本次数据库提交生成一个检查点计划。业务 SQL 与游标 SQL 都使用同一时刻、任务 ID、`running` 状态和租约令牌；游标写入成功后才更新内存进度。适用于开始快照、暂存页、配额、DNS 批次（含失败次数）、库存写入、续期日志和同步完成通知。

Cloudflare 队列任务在获取页面及复核凭据后才生成计划，将 CF generation 和队列租约一起用于页面事务。外层游标在 CF 游标推进或 generation 删除之前更新，此时两个租约条件都可检查。两步均在同一个 `batch()` 内，SQL 错误会使本页库存、候选、CF 进度和队列游标一起回滚。未通过队列调用的 CF 分页继续仅使用自身的 generation 和租约。

通知先完成加密、验长和分块，然后才绑定生产者租约。独立到期扫描也在此时检查中断、取一次时间，密文入队与扫描游标据此共同提交。通知**入队**与外部通道**送达**仍是不同状态。

续期发送前的原有日志查询同时检查工作租约；查询返回后再检查中断。已经留下 `attempting` 但结果不明时仍只读核对。租约判断是构造批次时的准入判断，事务中仍核对数据库里的令牌；既不是数据库硬实时截止，也不使远端 POST 和本地事务原子化。已经发出的请求无法撤回。

## 验证

用可控时钟覆盖租约截止前 1ms、恰好到期、4 个 DNS 结果同批提交、读页/加密过程中租约失效，以及续期日志落库后任务暂停。Cloudflare 两页测试在最终队列游标处注入 SQL 失败，验证存量未提前删除、恢复只重新获取第 2 页。隔离 workerd/D1 在相反方向注入 CF 检查点失败，验证先执行的队列游标也回滚，随后重试并完成。同组测试保留了不确定续期不重复 POST、通知独立重试和过期租约不可覆盖新持有者的既有要求。

复现：`npm run test:integration:cf-sync`、`npm run test:integration:notifications`；完整构建及双运行时冒烟使用 `npm run verify:all`。无 schema 迁移或新增调度资源。
