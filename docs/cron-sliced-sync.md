# Cron 与页面分片完整同步

本轮实现日期：2026-11-01。Worker 与 Node 共用业务入口；本轮只改源码并使用离线 fixture 验证，未部署或重启现有服务。

## 两条独立链路

- **Cron**：仅读取本地到期数据、发送有界合并提醒、处理预算允许的 DNSHE 续期及未知结果的只读核验。不查询域名列表、DNS 或实时 RDAP，不发现外部修改。
- **完整同步**：有效登录会话的可见页面或手动操作逐片推进。先显示缓存；每个 HTTP 请求最多一个上游页或一个有界数据库提交。关闭页面、隐藏标签页、退出登录或关闭开关后不再领取新片；已发送请求可能仍完成，不能保证远端撤销。
- 手动同步**不续期、不发送提醒**。绑定、批量绑定与更换凭据只做有界验证和保存，不通过 `waitUntil()` 拉完整列表。

现有 Worker Cron 时间和 Node UTC 定时参数保留。Node 的 `DISABLE_CRON=1` 只关闭定时提醒/续期，不替代页面同步开关。本轮原服务仍沿用该禁用设置。

## 设置

通过面板设置或已鉴权的 `POST /api/settings` 保存；这些是数据库设置，不是新增环境变量。

| 字段 | 默认/范围 | 语义 |
|---|---|---|
| `login_sync_enabled` | `"false"`；`"true"` / `"false"` | 升级默认关闭自动推进。关闭时只分页读取本地账号同步状态；手动按钮仍可推进 |
| `sync_freshness_seconds` | `"3600"`；60–86400 | 仅依据最后一次完整成功判断新鲜度 |
| `renew_threshold_days` | 保留，默认 90；1–3650 | 本地到期提醒阈值，不是续期许可 |
| `auto_renew` | 保留既有值；`"0"` 关闭 | 不擅自开启原本关闭的写操作 |
| `dnshe_renew_window_days` | `"0"`；0–365 | 必须明确配置；0 不发新自动续期 POST。不猜测 DNSHE 允许窗口 |
| `dns_records_cache_mode` | 保留历史设置 | 不会使 Cron 恢复 DNS 或列表同步 |

已发送但结果未知的续期，无论自动续期开关或窗口如何，后续只能 GET 核验；失败、未改善有效期或旧凭据身份不明时继续保留待核验状态，需要人工处理，不盲目再 POST。

2026-11-02用户确认到期前180天内续期免费；本轮仅记录确认，不自动配置180或执行续期。历史GET列表“续期”例不是写接口依据，逾期/赎回不套用普通免费窗口；真实写验收另授权。见[契约证据](provider-contract-evidence.md)。

## HTTP 与 Action

所有接口沿用面板鉴权。

- `POST /api/sync/plan`：`{ manual?, provider?, accountIds?, after? }`。本地 keyset 计划每页最多 25 账号；指定账号最多 50；返回 `plans/nextAfter/enabled`。不调用上游或一次创建全部任务。
- `POST /api/accounts/:id/sync-step`：`{ manual?, taskId? }`。返回 `taskId/version/accountId/phase/status/progress/continuation/retry_after_ms/last_completed_at/error/failure`。客户端不能提交自己的游标。
- 既有账号、服务商、全量同步入口返回 `syncPlan` 和本地计划；旧脚本若只等 `actionId`，需改为先取计划再逐次调用 `sync-step`，不能把开始响应当作完成。
- `GET /api/actions`、`GET /api/actions/:id` 展示任务权威投影；`POST /api/actions/:id/cancel` 停止后续推进。既有非分片 Action 保留。
- 普通失败为 paused 并退避；权限拒绝、不完整分页、损坏状态或 DNS 同期修改为 blocked。blocked 的显式手动重新同步建立新完整快照，不从损坏页盲目重试。取消不会因下次登录自动恢复；手动同步可以明确新建一代。

浏览器逐次等待响应，不使用固定睡眠猜测成功。每账号一次页面推进最多 500 片，未结束时保留断点供下次推进；每次请求最多等待 100 秒，包含 DNSHE 准入与传输时间。超时、旧会话或隐藏页晚到结果不触发成功回调。

### 排队/慢同步修复（2026-11-01）

- `queued` 是已提交断点、等待页面领取，不是服务端后台队列。自动同步关闭时明确显示“已暂停，请点击同步继续”；页面错误不再静默吞掉。
- 每页最多 25 账号各自顺序推进，不再先排空一个账号才处理下一个。慢请求或单账号失败不阻止独立账号；同 Key 的互斥、30/60s 和历史冷却仍由 D1 控制。
- 一次手动操作可按后端明确返回的 `retry_after_ms` 等待，在该操作开始后的 2 分钟窗口内继续同一 taskId，不自动重建完整快照。超长退避、HTTP 失败/超时、隐藏页面和退出登录保留断点并停止该次推进；不会擅自打开自动同步。
- 返回并展示断点更新时间、列表页数/域名数、DNS 完成数（历史任务没有该计数时不猜值）。重试剩余时间使用数据库时间，不受 Node/Worker 应用时钟偏差影响。
- 开始、阶段切换、DNS 进度里程碑、暂缓/受阻、恢复和完整完成写入“运行日志”。日志与游标共享 fencing 和原子 batch，不额外消费 D1 调用；未知已提交响应不会重放成功日志。只有完整完成写 success；上游错误原文/凭据不写新日志。
- 运行日志和同步提示的界面行为以下一节为准，已取代原每 15 秒固定刷新设计。

### 预算诊断与安全续跑（2026-11-02）

- DNSHE 生产准入使用秒级数据库时钟：正的滚动窗口等待向上取整到整秒，避免 `+1ms` 到期边界反复查询耗尽 D1。只延长等待，不缩短滚动窗口、不清理历史状态；等待仍可取消并受原队列期限限制。离线精确时钟 fixture 保持精确等待。
- 预算错误在拒绝新调用时记录 `resource/reason/used/reserved/limit/remaining/requested`，预留子预算不足另记 `reservation_remaining`；随后释放或收尾不会改变这份计数。同步任务错误和同一原子 batch 的日志附带这些明细及 `phase`，不记录凭据、URL 或上游原文。旧日志缺失的计数不会补猜。
- 只有 `exhausted` 且没有未知上游结果，并且暂停断点提交及权威读取均成功时，`sync-step` 才返回 HTTP 200、`paused/continuation=true/budget_yield=true`。保留原游标，至多 1 秒后允许下一独立请求继续；这是分片暂停，**不是完整同步成功**。权威读取使用原 3 次 D1 收尾预留，不从已耗尽的主预算读取。
- 手动推进或已启用的可见页面流可等待明确的预算暂停，继续同一 taskId；沿用操作开始后 2 分钟的等待窗口。连续三次预算暂停（中间没有返回已提交的 queued 分片）停止并显示错误，避免对不可能完成的单片反复请求。每账号每轮 500 片、页面生命周期和上游冷却保护保持不变。
- `closed`、未知上游结果、暂停提交/读取失败或 fencing 不匹配仍返回错误；浏览器不会因错误码是预算不足就重发。旧的 300 秒预算暂停不追溯修改，重启也不会自行推进已有断点。
- D1/external 默认各 40 次不变；Node 沿用共同应用策略，不表示 Node 受 Cloudflare 的同一平台硬限约束。本轮只修改源码、运行独立离线门禁，不重启、部署或触发真实同步/续期。

### 操作中心与增量日志（2026-11-01）

- 删除各页面顶部的同步小字；账号、阶段、列表/DNS 计数、错误和最后完整成功统一收进顶栏操作中心，配合进度条显示。进度是阶段估算，不是耗时百分比；只有完整成功才显示 100%。
- 操作中心合并页面推进状态与服务端 Action，不重复展示同一 taskId；较新权威版本不被旧页面状态覆盖。`queued` 仅是已保存断点，自动同步开关开启或有待续断点本身不会被计作正在执行；过期 running 租约也不保持活动轮询。
- 首次进入、展开操作中心、手动刷新或操作结束时可读取一次本地数据。空闲时不定时刷新运行日志或操作中心；正在执行的任务、面板操作、Scanner 或页面同步存在时，可见日志页约每 1.5 秒顺序读增量，活动结束补读一次。隐藏页面/离开日志页停止日志轮询，退出会话取消旧读取；恢复可见时只恢复仍有活动的日志流。
- `GET /api/logs?after_id=N` 沿用面板鉴权，只读本地数据库，单次最多最近 100 条，返回 `nextCursor`；初始/手动刷新读最近 100 条。增量按 ID 去重并正序追加到瀑布流时间线，仅保留最近 100 条；空增量不清空列表，不整表切换加载态。详情可折叠，用户向上阅读时不强制滚到底部，可点“跟随最新日志”。超过 100 条的突发日志按“最近 100 条”窗口截断，不承诺完整审计归档。
- 自动读取采用有界增量短轮询，不是 SSE。读取日志或任务不会同步、续期、恢复 Scanner，也不调用上游 API；清空日志后的全量读取会隔离旧增量响应，旧会话和取消请求的晚到结果不会发布。

### 全局跨页调度与密集DNS（2026-11-02）

- `advancePlan()`使用一个全局最多25账号顺序流池、最多一页待派发；流释放槽位即可加入后续页，不要求本页全部收尾。每页25、每账号每轮500、手动两分钟窗口和各40预算不变；满池/超时仍可延迟后页，不保证无限公平。
- 隐藏/退出/卸载/取消/迟到页与错页隔离、不重入同账号，51账号真实React/Chromium合成API回归通过；不是真实OS后台节流或Worker崩溃证据。
- 单页UTF-8 JSON 32768/32769字节、4/5页×100条的128KiB累计及坏ID回归通过；超界保持旧缓存，未完成不能成功。深历史三个增量索引保持保留策略，云端初建/扫描/CPU仍待验，见[规模说明](sync-scale-assessment.md)。

## 完整性与安全边界

- 七家使用单页读，DNSHE 列表每页 100，CF 每页 50。列表最多 200 页；分页元信息、稳定 total、重复 ID/名称、游标进度必须通过校验。DigitalPlat 未确认分页/meta 不虚构契约。
- 列表先捕获候选版本，全部分页保存 seen 后每片最多发布 20 行；最后每片最多检查 40 行删除候选。单调 mutation clock 与删除 tombstone 防同秒修改、同期注册/删除及旧列表覆盖确认续期。ID 与其他账号冲突明确失败，不迁移或覆盖其他账号数据。
- DNSHE 单域 DNS 片段连续且全部完成后才发布；单片 JSON 最多 32 KiB，单域合并快照最多 128 KiB、50 页。超界、不完整或片段缺失保留旧 DNS 快照，不能标记完整成功。未核验的 `dns_dirty` 阻止假完整成功；SQL 原子断言防晚到修改。
- generation、账号 revision、version、phase、owner 和数据库时间租约共同 fencing。业务写与游标在同一原子 batch 内；未知 batch 结果读取权威版本，不在同次执行重放业务写。
- 续期先持久化 prepared/sent，调度准入后、真实 fetch 前再次检查身份与意图。未知结果保留 verify，只读核验；同步不回退已确认的新有效期。
- HTTP/Cron 默认 external 与 D1 各 40 严格预算，涵盖 schema、鉴权、协调、日志和提交；收尾独立预留。Cron 候选最多 4，是否尝试取决于剩余预算，不承诺每轮续期 4 个。
- 通知按 UTC 日期、`local-expiry-v1`、渠道去重；确认成功才标记 sent，失败/未知退避 1 小时。最多收集 100 条提醒并提示截断，最终报告最多 3500 字符；不承诺网络未知结果严格只送达一次。续期积压写入警告日志。
- DNSHE当前仍按Key滚动30/60s和历史冷却保护；用户已确认同账号多Key合计共享30/min，**代码尚未按账号归并预算**，缺可靠主体/映射，不按别名猜归属。现有按Key防护不保证同账号多Key合计或面板外程序额度；不增加固定双槽、不清状态或换Key绕额度。

### Node SQLite 租约类型兼容（2026-11-02）

- Node SQLite 将 JavaScript `number` 绑定为 SQL REAL；旧领取 SQL 的 `json_set(..., '$.leaseUntil', ?)` 可能写出 `1793547434000.0`。数值虽是安全整数，原 SQL 仅接受 JSON integer，导致过期租约仍被拒绝领取，而 JS 解析通过后继续等待，最终报本地排队超时；该错误不代表 DNSHE 返回了官方 429。
- 领取校验只对 `leaseUntil` 兼容 integer/real：必须是数值、非负、在 JS 安全整数范围内，且与 INTEGER CAST 相等。不对存量小数直接截断；字符串、溢出和损坏状态仍拒绝准入。owner、events、最多 30 条事件和 4096 字节状态的原校验不变。
- 后续领取只将新的租约参数显式 CAST 为 INTEGER；不修改通用 D1/SQLite 数字绑定、不清历史状态、不新建限频通道。旧状态仅在正常领取且原租约已过期后原子接管，事件数组保持原样，正常发送准入才按原窗口规则过滤过期事件并计入新授权。
- 有效租约、已满滚动窗口、历史冷却、取消、fencing、未知请求结果与各 40 次预算保护均不放宽。既有同步 taskId/游标及退避不追溯修改，不因升级自动继续同步；需要有效页面/手动操作按原规则推进。
- 回归只使用独立 Node SQLite/workerd/D1 fixture 和合成响应，不执行真实同步、续期或 Scanner。本批改源码及离线构建，不重启、不部署；原数据库/AES和当前运行副本不改。

## 升级与验收

schema升级只增加任务、mutation、续期意图、通知送达表和索引，不清空原账号/域名/DNS/Scanner断点/Action/AES。业务JSON迁移另有500行/8MiB、异Key重加密/本地ID映射、预览→确认追加/原子审计约束，不是整站恢复；见[迁移发布手册](release-and-migration.md)。原构建产物和运行服务不因源码修改自动更新。

上线需独立授权：数据库与 AES 成对备份、验证迁移、停止同库旧写入实例、少量真实只读同步，再单独授权续期；最后观察云端 CPU、D1 读写行/调用、每日用量和积压后决定开关。不要直接启动不理解新迁移的旧版本回退，也不要通过清限频状态恢复。
