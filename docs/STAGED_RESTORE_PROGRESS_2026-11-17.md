# 第五批：持久 staging 分段恢复

> 本文记录修复阶段状态；“未提交/推送/部署”指当时。后续主分支发布范围见[发布说明](./RELEASE_NOTES_2026-11-17.md)。

后续[同步队列修复](./SYNC_QUEUE_FIX_2026-11-17.md)已新增 schema v4，当前 15 个显式索引；以下是第五批当时的范围。

实现业务快照超过 500 行的分段恢复。本批未提交、推送、部署或访问生产 D1；持久后台同步执行器仍未实现。

## 已实现

- 新增 schema v3：`restore_sessions`、`restore_chunks`、`restore_rows`，以及 3 个索引。此前 v1/v2 的记录和业务数据不重写。
- 新库 SQL 快照与 Worker/Node 迁移保持一致；当前共有 11 个显式查询索引。
- 创建会话、按序上传、读取状态、完整校验、最终提交和取消均有独立 API。
- 上传仅写 staging；块内容、块标记和 next_chunk 在一个事务中提交。失败块全部回滚，不丢已完成块。
- 分块有摘要、连续偏移和行数；重试同一块幂等，不同文件不能复用同一会话 ID。
- 完整校验重新检查总摘要、原快照 checksum、密钥、跨块唯一性、引用和目标身份冲突。
- 原始块使用 AES 加密存储；历史 plain: 凭据在规范化 staging 中升级为 AES，不以弱编码新落盘。
- 明文清单只允许版本、行数、摘要等固定字段，不接受额外凭据、原始内容或虚构的导入表统计。
- 会话绑定登录 token 的 SHA-256，不存明文 token，不允许另一登录会话读写。创建与最终提交继续遵守已配置 2FA。
- 超过 500 行的前端流程自动使用 staging，展示进度、预览并等待用户确认。刷新后重新选同一文件可续传。
- 本地仅保存 scoped 会话 ID/快照摘要，按后端地址和登录 token 哈希隔离。文件更换或会话变化会停止旧上传。
- 最终提交为 5 个按表执行的 INSERT/SELECT UPSERT，连同状态切换和 staging 清理在一个事务中完成，不生成每行一条业务写入语句。
- 最终事务保留身份 fence；SQL 错误、身份竞争或取消竞争不得提交半份业务数据。
- 提交成功后清除块和行数据，保留 24 小时回执；响应丢失后重试不会再写一遍。取消不能回滚已完成的数据。
- 未提交会话在创建后 1 小时过期；后续创建会话时清理过期记录。不是每分钟自动清理，停止使用时过期记录可能暂留。
- 新增 no-store 响应和近期/活跃会话预算，限制暂存资源增长。

## 使用方式与边界

1. 选择 JSON 业务快照，填写当前动态码，点击“验证并预览”。
2. 小快照仍使用原直接入口；超过 500 行自动小块暂存。
3. 上传和校验成功后核对预览，再填写当前有效动态码、确认提交。
4. 中断时重新选择相同文件，仍需相同后端和原登录会话；登出重新登录后的 token 不具备旧会话权限。
5. 有冲突时业务表保持不变。解决数字 ID/自然身份映射后作为新文件开始新会话；本批不自动重新编号。

初版限制：

- 总计最多 10,000 行、500 个 API 账号、8MB 规范上传内容。
- 每块最多 20 行、256KB；文件读取的原有 20MB 上限仍有效。
- 每登录会话最多 2 个活跃会话，全库最多 4 个活跃会话；未清理记录还有每 owner 20 个、全库 100 个预算。
- 上传有效期 1 小时，成功回执有效期 24 小时。

这是**人确认的分段恢复**，不是关页后自动上传或自动提交的后台作业。没有上游 API 写操作，不覆盖密码/2FA/会话设置，不删除目标独有业务记录。

仍未实现：自动 ID 映射、字段级三方合并、任意大快照、完整灾备或租户化数据库。身份判断沿用当前字段语义；旧数据大小写/Punycode 等规范化问题需单独整理。升级应在维护窗口进行，避免其他同步任务同时更新同一业务数据。

## 双运行时修正

旧库字段检查改为 `VALUES` 驱动的表值 PRAGMA，一次读取所需元数据，避免冷请求逐表读、冗余 CREATE 的查询预算。

验证中发现 D1 的复合 SELECT 限制比 Node SQLite 严格，最初 UNION 方案虽通过 Node 测试，仍在 workerd 报错。已改用 VALUES 方案并完成真实 workerd/D1 冒烟；不能以 Node 测试代替 Worker 验证。
