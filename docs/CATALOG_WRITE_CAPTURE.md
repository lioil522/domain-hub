# 摘要变更日志与索引写入开销：隔离实验

基于 `c311d83`。本次仅在全新内存 SQLite／Miniflare D1 库安装行变更触发器和依赖索引。**不改生产 schema、写入路径、刷新协议或默认摘要。** 使用 `npm run test:prototype:catalog` 运行专项回归，`npm run benchmark:capture` 重现写入对照。

## 捕获和修复范围

- `domains_cache`、`custom_domains`、`domain_date_overrides` 记录旧／新行 ID 和原始域名。账号事件仅记录 ID，用于查找该账号下受影响的域名。删除事件保留旧值，不依赖查找已经删除的父账号。
- UPDATE 按摘要相关字段比较新旧值。仅刷新托管行 `updated_at` 不追加事件；手动日期表的 `updated_at` 决定覆盖顺序，不能忽略。
- 缓存仅匹配精确的活动 RDAP 前缀；写入、改键和物理清理会产生事件。日志不保存缓存值、凭据、用户备注或其他行载荷。**时钟走到 RDAP 到期点不会触发 SQL 日志**，仍需读端有效期或显式调度。
- 回归使用真实 JSON UPSERT 辅助函数、同一事务内差集删除，以及外键级联。测试确认后续语句失败、日志插入失败时，业务行、版本戳与日志不会部分提交。测试还确认关闭 SQLite 递归触发器时，`INSERT OR REPLACE` 的隐式删除不会留下旧键；该写入形态不在支持范围。
- 归一化沿用共享 JS。依赖索引保存源行的归一化键、剥离不可见字符的候选键与所属账号。日期查询通过两个索引找到匹配的归一化键，不会把不同域名合并。索引回放按最多 256 个事件一页，仅查询涉及的源行 ID；只改变到期日期的来源行不重写依赖索引。

回放仅在没有并发写入的测试库运行：本页涉及的来源以当前行状态为准；没有事务边界标记、持久消费位点、并发改名防护或日志清理。账号大范围失效、日期解析层重新择优以及摘要贡献物化都未计入回放。

## 写入对照

`benchmark:capture` 各用一个全新的内存库测 100、1,000、10,000 条托管行。在 10,000 行组，模拟同步保留 8,000 条不变、调整 1,000 条到期日、插入 1,000 条、差集删除 1,000 条；随后原样重跑，再更改 1 条日期覆盖并删除托管账号。采用真实 JSON UPSERT 和相同的差集删除形态，不执行上游 API、同步队列或租约。

以下为 10,000 行组 **本地 workerd/D1 报告的 `rows_written`**，并非生产计费：

| 操作 | 无日志 | 捕获时 | 回放依赖索引 | 日志事件 |
|---|---:|---:|---:|---:|
| 混合同步 | 61,000 | 64,002 | 4,000 | 3,000 |
| 原样重跑 | 60,000 | 60,000 | 0 | 0 |
| 日期覆盖 | 1 | 3 | 0 | 1 |
| 删除账号及子行 | 10,002 | 20,005 | 10,000 | 10,002 |

混合同步额外约 11.5%，删除账号加索引回放约为原写入的 3 倍。日志捕获没有降低原样重跑的**原有** UPSERT 写入成本。在这次样本里，10k 依赖索引初建约 153ms，混合同步后回放约 63ms，级联删除后回放约 147ms；单次本地墙钟仅供复现，不是生产 CPU、延迟承诺或行数定价推算。Node 适配器的 `rows_written` 主要反映直接变更，不可用来计量隐式触发器、级联或物理索引写入；用实际日志事件数和依赖表变化分别核对。

## 决策

保持现有业务方案。触发器可为受控写入形态提供准确的脏键线索，但级联开销、日志保留与清理、消费时序和 RDAP 自然过期仍需要方案。若继续，优先对比专用事务内脏键表和追加日志的写入放大，并验证大批事务能否合并同一域名的重复失效，不接入生产前先解决失败回滚和读端过期边界。
