# 首批安全与数据一致性修复

基线分析见 [全仓分析与优化方案](./PROJECT_ANALYSIS_2026-11-17.md)。本文记录第一批代码修复，不代表整个优化方案已完成。

## 已实现

### 1. 认证配置与初始化

- 认证配置读取失败或凭据不完整，返回 503，不再被当作未初始化。
- setup 使用数据库唯一 claim，claim、用户名、密码哈希与盐在同一事务中提交。
- 并发初始化最多一个成功，失败者不能覆盖已有管理员或签发成功会话。
- 修改密码使用原子批量写入。
- Settings 写入、会话写入与撤销不再吞异常；会话读取失败与过期分开处理。
- 过期登录失败计数下一次失败重置为 1；限流存取失败不再视为没有限制。
- 限制登录和初始化凭据长度，避免无界输入进入密码计算。

### 2. 两步验证

- 新密钥保存在独立 `auth_2fa_pending`，有效期 10 分钟。
- 生成密钥要求重新验证登录密码；已启用的 2FA 拒绝重新 setup。
- 验证动态码后通过 CAS 原子激活；密钥被替换、过期或并发激活时，旧操作不能成功。
- 关闭 2FA 要求登录密码与现用动态码，并对现用密文进行 CAS。
- 活跃密钥缺失或无法解密时，登录失败关闭，不绕过 2FA。
- 设置页增加密码确认输入，显示待激活密钥的有效期。

**换绑方式：**验证密码与旧动态码后关闭原验证器，再重新开启。此次没有增加可绕过旧验证器证明的直接换绑接口。

### 3. Cloudflare 分页同步

- 手动与 Cron 共用 `syncCloudflareSlice()`。
- 新增 `cf_sync_state`、`cf_sync_seen`，记录持久分页、同步周期、已看到的对象及初始删除候选。
- 每页写入、已看到对象标记及游标在同一事务中提交。
- 只有完整周期结束才清理未被看到的初始候选，跨调用续拉不会误删前页。
- 新增账号租约与写入 fence，过期执行者不能写入、清理或释放新执行者的租约。
- 中途失败保留已提交页；新调用继续最后检查点。
- 同步中通过其他操作新增的缓存行不作为本周期删除候选。
- 异常或不完整的 Cloudflare zone 响应不被解释为权威空列表。

**兼容行为：**第一次运行新同步器从第 1 页重新建立周期，不沿用旧 `cf_zone_cursor:*` 缓存。已有域名缓存保留，旧缓存最终正常过期。

### 4. 加密与前端错误契约

- 新 Secret 写入必须配置 AES_KEY，取消 Base64 弱编码降级；历史 `plain:` 数据仍可读取。
- 通知配置加密失败不再保存原文。
- 业务级 401/403 不再自动退出登录；只有明确的会话失效/缺少认证响应才清会话。
- 登录 hook 正确处理异常中的 `need_2fa`、`not_initialized` 等业务响应。
- API 默认使用同源相对路径；普通生产构建不再依赖必须烘焙后端 URL。

### 5. 运行时依赖

- `hono` 更新到锁定版本 4.13.19。
- `@hono/node-server` 更新到锁定版本 2.1.8。
- 根包生产依赖 `npm audit --omit=dev` 为 0。
- 未执行强制主版本升级；Wrangler/Miniflare 开发链及前端工具链告警仍需后续处理。

## 升级注意

1. 先备份数据库及当前 AES_KEY，不能为了本次升级随机替换密钥。
2. Worker 必须配置原有稳定 AES_KEY。缺少密钥时，新的账号凭据、2FA 与敏感通知配置无法保存。
3. Node 自建仍可使用数据目录里自动持久化的 AES_KEY。
4. 两张同步状态表由现有自举逻辑幂等创建，`schema.sql` 同步更新；没有删除或改写已有业务字段。
5. 已启用 2FA 的密钥保持原格式；升级前未完成的 2FA 设置需要重新生成。
6. 后端返回无效会话的错误码现为 `session_expired` / HTTP 401；业务密码/TOTP 错误仍保留登录态。
7. 前后端一起发布，避免旧前端仍按所有 401/403 清会话，或不提交新的 2FA 密码确认字段。
8. 不建议回滚到原有分页同步实现；它可能重新误删缓存。数据库新增表本身无需删除。
