# 第六批：修复同步一直 running / 排队不执行

> 本文记录修复阶段状态；“未提交/推送/部署”指当时。后续主分支发布范围见[发布说明](./RELEASE_NOTES_2026-11-17.md)，实际部署效果待线上验证。

本批修复的是代码及任务恢复机制，没有访问或改写线上 D1，也没有提交、推送或部署。

## 原因

- 旧同步把整个账号列表、解析查询及通知放在一次 HTTP waitUntil 中；响应后的执行时间有限，进程中断没有执行器接管。
- actions 保存状态但没有持久工作项、租约或后台消费者，generic API 还能创建无执行参数的 sync 记录。
- 单个大账号回源过多或网络长时间不结束，会让后面的账号等待；旧状态没有失联回收。

## 修复范围

- schema v4 新增 `sync_work`、`sync_rows`、`sync_candidates`、`sync_renew_journal`，当前共 15 个显式索引。
- 绑定、换凭据、单账号/服务商/手动全量同步统一创建持久工作项；返回 action_id，不再依靠序列化闭包恢复。
- 账号工作项使用 90 秒租约和写入 fence，领取 CAS，取消/过期执行者不能提交或释放新执行者的租约。
- DNSHE 列表逐页拉取，解析记录每切片最多 4 个；页数据及游标原子提交，完整权威周期才差集清理。
- CF 保留已有分页/seen 周期，单切片一页；一页写入改为常量数量的 JSON SQL，避免 50 个 zone 生成 100+ 条语句。
- CF 增加凭据指纹；换 Token 后旧客户端不能提交，下一周期从第 1 页重新建立正确范围。
- 解析结果未知保留既有 DNS 状态，明确失败，不冒充成功；读取失败和限流有有界重试/退避。
- 每个切片默认 12 秒总期限，上游读取另有 15 秒及 5MB 响应上限；超时包括响应体，不仅是连接。
- 配额刷新是辅助工作，先提交域名检查点，配额超时不能让账号永久停在第一步。
- 更新过期租约，恢复最后已提交游标；5 次连续无进展失败或超过 24 小时总期限明确失败。进展检查点重置连续失败计数。
- 旧的 sync queued/running 记录无工作项且 15 分钟没有更新时标记失联失败；保留原参数与历史，支持有账号清单的显式重试。
- 不猜测缺失的旧任务参数；没有账号清单时提示在对应服务商页面重新发起。
- 操作中心展示逐账号阶段、拉取/检查数量和重试时间，新增暂停、重试/继续与取消；拒绝手动伪造同步 completed 或任意 PATCH 状态。
- 完成/失败/取消后的临时快照保留一天，小时级维护清理，动作历史保留。未确认续期日志不随临时快照清理。

## 执行方式

### Node

启动后和每秒运行持久队列，不依赖浏览器。DISABLE_CRON=1 仅禁用原日常定时同步，不禁用手动队列执行。退出时停止周期领取并尽量等待后台任务；硬中断的工作在租约过期后回收，不会永远 running。

### Worker

配置新增每分钟触发器 `* * * * *`，负责兜底推进和租约回收。已有每天两轮的 Cron 同步/到期提醒流程继续保留，尚未整体迁移到该工作队列。

初次请求及操作中心查询也会唤醒短切片，但不是唯一执行来源。**必须部署新的分钟触发器**；只替换前端或漏掉触发器，关页后的兜底不会生效。

没有 Queue binding 时，一次兜底调用推进一个切片，较大账号会比较慢。高频推进可选 Cloudflare Queues；本批没有创建云端 Queue，也没有默认绑定未创建的资源。

可选配置（先创建队列，并把名称换成自己的）：

```toml
[[queues.producers]]
binding = "SYNC_QUEUE"
queue = "domain-hub-sync"

[[queues.consumers]]
queue = "domain-hub-sync"
max_batch_size = 1
max_batch_timeout = 1
max_retries = 5
```

消息只负责唤醒，D1 工作项才是权威状态；重复消息不会绕过租约，发送失败仍由分钟触发器接管。触发器数量与 Queue 成本/计划限制请在上线前确认。

## 续期安全

全量手动同步仍包含 DNSHE 到期续期。续期 POST 前保存持久日志；结果可能已生效但回复丢失时只用 GET 核对，不盲目再 POST。记录确定的新期限，防止后续任务因上游列表暂时陈旧而再次续期。日常 Cron 也遵守未确认记录。

外部 API 没有可依赖的跨系统事务保证；不宣称 exactly-once。无法确认时明确失败，需要核对上游；取消不能回滚已发出的续期。通知为有界、至多一次尝试，可靠通知 outbox 仍未实现。

## 限制与上线注意

- 单动作最多 500 个账号、单账号最多 10,000 域名。
- DNSHE/CF 有持久分页；其他服务商的上游列表仍由现有 SDK 聚合，聚合有时间及 1MB 检查点预算。过大/过慢列表明确报错，不会一直 running；并非所有 SDK 都实现了持久分页。
- 账号已有不同模式或暂停任务时，需要继续/取消原任务，不静默并行创建另一份。
- 前后端、schema v4 与调度配置一起更新，保留原 AES_KEY，升级前备份。运行中不要手工改工作项、租约或版本号。
- 旧任务是标记失联并重试，不是偷偷标记完成；不会删除账号或域名来“解卡”。
- 此代码尚未上线，无法据本地测试宣称线上卡住的账号已经恢复。
