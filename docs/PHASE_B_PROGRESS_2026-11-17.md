# 第二批：扫描可靠性与真实同步结果

本轮基于 `58c53e8`，落实后续计划中 Scanner 错误分类、完成检查点、限流重试，以及后台同步结果传播。没有完成整个 B/C/D 阶段，也没有提交、推送或部署本轮代码。

## 已实现

### Scanner

- 只有成功响应中明确的布尔注册结果才记为已注册/未注册；网络异常、非 JSON、错误状态和模糊结果均为未确定。
- 未确定项自动暂停，保留待重试；恢复时重入队，不增加已确定计数。
- HTTP 429 保留 Retry-After，支持秒数及 HTTP 日期；代理返回非 JSON 时也不丢失该信息。
- 请求增加可取消的 15 秒期限；重置、会话切换、后端切换和卸载可取消旧运行，旧响应不能污染新结果。
- 执行器记录连续完成低水位和越过低水位已完成的索引。领取任务不推进断点；恢复不漏掉未完成根域，也不重查已完成的越序项。
- 每个账号流水线使用单调时间检查请求间隔，提前唤醒的定时器需要重新检查。浏览器运行最多使用 16 条流水线。
- 保存 v2 快照：原规则、实际使用的词库、后缀顺序、过滤选项、连续完成位置、越序完成项、未确定项、限流等待以及已发现结果。
- 断点按后端地址隔离并校验结构。旧版缺少完整配置的断点仍可看见，但拒绝猜测恢复；需确认重新开始。
- 本地保存失败会暂停并明确提示；只能保证恢复最后成功保存的检查点，不将存储失败包装为成功。
- 查重池预取改为有界串行后台请求，不再为所有 chunk 一次性启动 Promise。
- 前缀与根域名的组合任务上限为 30 万，在创建任务数组前检查；超大规则需要分批。

**仍是浏览器扫描。** 关闭页面后不会继续在服务器执行。本轮没有把 Scanner jobs 状态接口伪装成持久后台执行器。

### 同步与操作中心

- 同步返回逐账号结果：completed、paused、failed、skipped；记录数量、下一页及错误信息。
- DNSHE 解析记录失败保留已知状态，但账号任务标记失败，不再被外层当作成功。
- DNSHE 回源并发最多 5 个；权威空列表可清理旧缓存，重复/不完整/超过预算的分页不得执行全量差集删除。
- DigitalPlat 非数组的成功响应不得被当作权威空列表清理缓存。
- Cloudflare 已提交但未完成的切片标记 paused，继续保留首批引入的持久分页与租约。
- 全量同步汇总包含续期失败；Cron 配额中断后不再把未完成账号的轮转位置直接越过去。
- 绑定、换密钥、单账号、服务商和全量同步返回 action_id；同步启动响应与完成结果明确区分。
- 操作中心保存并展示逐账号结果，后台完成/失败回调通过条件更新，不能覆盖已取消或其他终态。
- 取消将在下一个账号开始前检查；已经执行/提交的当前账号或切片不会回滚。
- 前端改为查询操作状态，不再用 3–5 秒延迟或域名缓存指纹证明完成。超时、部分提交及失败不会显示“同步完成”。
- WHOIS 限流保留 HTTP 429、错误码与 Retry-After；无法确定注册状态的上游结果不能进入已注册查重池。

**任务状态持久化不等于执行持久化。** HTTP 后台仍使用现有 waitUntil/Node 执行方式。进程或 Worker 中断时任务可能停留在 running；队列/Workflow、完整作业租约和自动恢复仍待后续。

## 测试与验证

新增 36 个回归用例：

- `tests/unit/scanner-runtime.test.ts`：20 个客户端分类、断点、限流、取消、存储和任务预算用例。
- `tests/integration/sync-results.test.ts`：16 个逐账号结果、操作状态、分页、WHOIS 与 API 用例。

新用例接入现有 `test:invariants`，总计 91 个不变量/集成用例，另保留 Node/SQLite 等既有自检。

已通过全量验证、前端普通/自建构建、Node 构建及本地 Workers/Node 基础冒烟。本地 workerd/D1 额外验证了失败状态传播、已知 DNS 状态保留、分片暂停和取消回调保护。未使用真实上游凭据、线上数据库或云端部署。

尚未做真实浏览器交互 E2E、性能测量或 Docker 镜像构建。

## 升级注意

1. 前后端一起更新；新前端按 action_id 查询，新后端新增 paused 状态及逐账号汇总。
2. 当前没有新增数据库表，继续使用首批状态表、actions 及已有业务表。
3. v2 断点不迁移旧版缺失数据，也不自动删除词库、其他后端的 v2 断点或生产数据。
4. 30 万是任务总数上限，而不只是前缀上限；选择多个后缀时需缩小规则。
5. 本地存储仍有浏览器容量限制，出现保存警告时先导出结果、清理空间，不能假定刷新能恢复最新内存进度。
6. 不建议将客户端限频理解为跨浏览器/跨所有任务的全局服务商限流，后续需要服务端协调。
