# 第三批：数据库版本迁移与索引一致性

> 本文记录修复阶段状态；“未提交/推送/部署”指当时。后续主分支发布范围见[发布说明](./RELEASE_NOTES_2026-11-17.md)。

以下记录第三批范围。后续[分段恢复](./STAGED_RESTORE_PROGRESS_2026-11-17.md)已新增 v3、3 张暂存表和 3 个索引，当前共 11 个显式索引。

基于本地提交 `e0d3e81`，处理分析报告 P1-13。此批未提交、推送或部署，不涉及生产数据库。

## 已实现

- Worker 与 Node 共用 `src/db/schema-migrations.ts`，不再各自维护建表流程。
- `src/db/schema-definition.ts` 是新库结构的唯一声明；`schema.sql` 为生成快照。`check:schema` 已接入全量验证，拒绝快照漂移。
- 新增 `domain_hub_schema_migrations`，记录版本、名称和应用时间；不是 Wrangler 的 `d1_migrations`，也不是业务备份数据。
- v1：创建缺失业务表，补充已知历史字段。v2：创建所需查询索引。每个版本的 SQL 与版本记录在同一事务中提交。
- 已知历史字段包括账号 provider/website、域名 dns_provider/provider_account_id/remote_id，以及手动域名 registered_at。
- 同一 binding 的并发初始化共用进行中的 Promise，不保留跨数据库的全局成功标记。不同 isolate/连接的竞争只有在对方已提交完整迁移版本后才被当作成功。
- 已完成迁移的正常请求只读小型版本表，不重复执行 CREATE、ALTER 或 PRAGMA；新库不逐表查询不存在的表，减少首请求查询预算。
- 未来版本、断裂/不一致版本记录、无法读取数据库、未知缺失字段均不被当作新库。失败保留 503/启动失败语义，后续请求可重试。
- Node 在监听端口和启动 Cron 前执行迁移及表/字段/索引检查；缺少默认外部 SQL 文件不影响初始化。
- 明确配置 `SCHEMA_FILE` 时仍会读取该文件作为迁移前扩展；文件缺失或执行失败将阻止启动。不再隐式执行工作目录中的文件。

## 索引

已有 SQL 快照中的 4 个索引统一覆盖运行时建库：

- `idx_domains_account`
- `idx_domains_expires`
- `idx_logs_created`
- `idx_cache_expires`

新增 4 个查询/外键索引：

- `idx_domains_account_expires`：单账号域名按到期时间排序。
- `idx_actions_updated`：操作中心按更新时间取最近记录。
- `idx_custom_domains_account`：可选手动账号的关联和级联删除。
- `idx_custom_domains_expires`：手动域名到期列表。

发现同名但定义不同的索引时停止升级，不自动删除或覆盖操作者的自定义索引。其他列、表、索引及业务数据均保留。

**没有增加 nullable 手动账号的唯一索引。** P1-14 的已有重复行、备注/日期冲突仍需单独设计修复流程；本批不会静默合并或删除这些记录。

## 验证

新增 `tests/integration/schema-migrations.test.ts` 共 19 个用例：

- 新库、旧库、生成 SQL 快照结构一致。
- 保留账号 ID、凭据密文、2FA 数据、域名日期与备注。
- 重复运行只查版本；20 个并发管理器及独立 binding 竞争。
- ALTER 和索引批次失败回滚，不记录虚假成功版本。
- 数据库读失败、未来版本、历史断裂、同名索引冲突。
- 更换 binding 不继承另一数据库的 readiness。
- API 初始化失败不执行管理员写入，Node 拒绝不完整 schema。
- 不改写自定义列、索引或历史 nullable 重复域名。
- 查询计划确认账号到期排序、缓存清理及操作中心查询使用索引。
- 新库初始化查询预算有界，不对不存在的表执行 PRAGMA。

本地 workerd/D1 冒烟已验证新库及旧账号表升至 v2、8 个索引齐全。实际 Node 进程已验证：空工作目录无外部 schema 文件也能启动；缺少必需索引时非零退出、未开放 HTTP 监听。

`npm run verify:all` 已通过：110 个不变量/集成测试、Worker/Node 类型检查、构建、既有 Node 自检和主题检查全部通过；Node 服务端单独构建也通过。本批未访问真实上游、线上 D1 或执行云端迁移。

## 运维边界

1. 升级前备份数据库及原 AES_KEY；本批不轮换密钥。
2. SQL 快照不写“已迁移”记录；仅创建表成功不能证明旧库字段已升级。
3. 自动迁移只支持已知历史结构，未知缺失字段或同名异构索引需要人工检查，不能靠删版本记录解决。
4. 大库首次创建索引可能耗时并持有写锁，应在维护窗口验证。限制并发不等于没有 D1 计费或时间限制。
5. 运行请求只核验迁移历史，不逐请求检查所有表、约束或索引。禁止运行中绕过迁移器修改结构；Node 启动结构核验也不是完整业务数据审计。
6. 回滚二进制前评估 schema 兼容性。本批为增量变更，未删除原字段；未来不兼容版本由旧程序拒绝，不能伪造低版本号绕过。
7. 后续 schema 变化必须增加新的迁移版本与实现，不修改已发布版本的含义；重新生成并提交 `schema.sql`。
